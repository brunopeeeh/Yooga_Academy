# AGENTS.md

Yooga Academy — React 19 + TypeScript + Vite SPA (pt-BR) that migrates a static HTML prototype
into an onboarding app for the Yooga support team. Local-first: the API layer exists (Phase 8)
but only runs when `VITE_API_MODE=api` is set — the default is zero network calls.

## Commands

```bash
npm run dev          # http://localhost:5173
npm run check        # typecheck -> lint -> test   (run this before finishing)
npm run typecheck    # tsc -b (project references, incremental)
npm run lint         # eslint .
npm run test         # vitest run
npm run test:watch   # vitest
npm run build        # tsc -b && vite build
npm run seed:extract # regenerate src/data/seed.json from the prototype HTML
npm run content:extract # scrape the Central de Ajuda into src/content/lessons.generated.json
npm run content:checks # generate the check questions into src/content/checks.generated.json
npm run content:quizzes # generate the module quizzes into src/content/quizzes.generated.json
```

- Single file: `npx vitest run src/domain/rules.test.ts`. Single test: add `-t "nome do teste"`.
- `npm run format` / `format:check` run Prettier over the whole repo (printWidth 100, single quotes,
  semicolons, trailing commas).

## Generated data — never hand-edit `src/data/seed.json`

- `src/data/seed.json` is generated by `scripts/extract-seed.mjs` from the `const SEED = {...}` literal
  inside `yooga-academy-onboarding-prototipo.html` (root). Run `npm run seed:extract` after changing
  that literal. Prettier and ESLint ignore both files on purpose — don't try to format them.
- The seed carries **catalog metadata only** (8 groups, 170 lessons: `id`, `ordem`, `titulo`,
  `tipo`, `url_central`, `origem`). Lesson body text lives in `src/content/curated.ts` (hand-written)
  and `src/content/lessons.generated.json` (scraped); quiz questions in `src/content/quizzes.ts`.
- `src/data/catalog.ts` validates the seed with Zod at import time, so a drifted seed crashes the app
  immediately. Keep `src/data/schema.ts` in sync with any shape change.

## Generated data — never hand-edit `src/content/lessons.generated.json`

- `scripts/extract-content.mjs` downloads the 170 Help Center articles (HubSpot KB) listed in
  `src/data/seed.json` and writes `src/content/lessons.generated.json`. No dependencies: the HTML
  parser is hand-written. Run `npm run content:extract`; `--refresh` ignores the HTTP cache in
  `.cache/central/`, `--only=<match>` previews one lesson without overwriting the file.
- The generated file is minified on purpose (~700 kB) and is ignored by Prettier and ESLint.
- `src/content/schema.ts` validates it with Zod at import time (`src/content/generated.ts`), so a
  drifted file crashes the app immediately. Keep the schema in sync with `src/content/types.ts`.
- `src/content/lessons.ts` merges curated content (priority) with the generated one and exposes
  `getLessonContent`. `src/content/ContentSteps.tsx` renders the step kinds and
  `src/content/InlineContent.tsx` renders the tokens (`text`/`strong`/`key`/`link`/`image`).
- The `/aula/:lessonId` route is **lazy** (`src/app/router.tsx`) so this payload stays in its own
  chunk and does not weigh on the initial bundle.

## Generated data — never hand-edit `src/content/checks.generated.json`

- `scripts/generate-checks.mjs` derives the "confere rápido" questions from the scraped text
  and writes `src/content/checks.generated.json`. Run `npm run content:checks`; `--only=<match>`
  previews one lesson without overwriting the file.
- The questions are **verifiable by construction**: the correct option is a literal excerpt of
  the lesson, the distractors come from sibling lessons of the same group and do not appear in
  the text. The shuffle is a PRNG seeded with the `lessonId`, so the output is stable.
- `src/content/schema.ts` validates the file with Zod at import time (`src/content/checks.ts`),
  so a drifted file crashes the app immediately.
- `src/content/lessons.ts` merges curated questions (priority) with the generated ones and
  marks the generated ones as `checksOrigin: 'rascunho'` — the lesson screen shows the
  "geradas a partir do artigo" badge so the content team can review them.
- `src/content/content.test.ts` is the permanent audit: the correct option exists in the
  lesson, the distractors do not, the sequence question points to the immediate next step and
  the two questions of a lesson never share the same answer. **Keep it green** when changing
  the generator — it is the safety net for a 198-question generated file.

## Generated data — never hand-edit `src/content/quizzes.generated.json`

- `scripts/generate-quizzes.mjs` builds the quiz of every module with `tem_quiz: true` from the
  scraped text and writes `src/content/quizzes.generated.json`. Run `npm run content:quizzes`;
  `--only=<match>` previews one module without overwriting the file.
- The questions are **verifiable by construction**: the correct option is a literal excerpt of a
  step of the cited lesson; the distractors come from other lessons of the module (or of the
  group, for thin modules) and do not appear in that lesson. Types: sequence ("depois de X,
  qual é o próximo passo?"), recognition ("qual destas ações é descrita na aula X?") and
  order ("qual destes passos vem primeiro?"). The shuffle is a PRNG seeded with the `moduleId`.
- `scripts/lib/lesson-text.mjs` holds the extraction helpers shared with
  `scripts/generate-checks.mjs` — both generators must agree on what a readable step is.
- Modules whose quiz is curated by hand (`src/content/quizzes.ts`) are skipped by the generator
  (`CURATED_QUIZ_MODULES` in the script) — the curated text wins at runtime.
- `src/content/schema.ts` validates the file with Zod at import time
  (`src/content/quizzes.generated.ts`); `src/content/quizzes.ts` merges curated quizzes
  (priority, `origin: 'curado'`) with the generated ones (`origin: 'rascunho'`) — the quiz
  screen shows the "gerado a partir dos artigos" badge.
- `src/content/quiz.test.ts` is the permanent audit: every `tem_quiz` module has a quiz, the
  correct option exists in the cited lesson, the distractors do not, the sequence question
  points to the immediate next step, the order question points to the first step and a quiz
  never repeats the same answer. **Keep it green** when changing the generator.
- The `/quiz/:moduleId` and `/resultado/:moduleId` routes are **lazy**
  (`src/app/router.tsx`) so the ~158 kB payload stays out of the initial bundle.

## Business rules live in one place

All thresholds are in `RULES` in `src/domain/rules.ts` — read them there instead of re-deriving:
lesson XP 10, XP per correct answer 5, seal XP 30, approval rate 70%, level XP 250. Levels:
Aprendiz, Praticante, Analista, Referência, Especialista.

Non-obvious rule behaviour:

- Quiz XP counts **only the delta over the previous best score** (`quizXpGain`). Retaking with the same
  or lower score awards 0 XP.
- Approval is sticky: a later failing attempt keeps `aprovado: true` from the previous pass.
- A seal is granted only when every quiz module of the group is approved. The store does **not** compute
  this — the screen calls `isSealEarned` and passes `sealEligible` into `recordQuizAttempt`.
- `lesson.tipo` is `essencial` | `consulta` ("consulta" = _leitura de apoio_). Only `essencial` lessons
  count toward progress and unlock the module quiz.
- A module quiz is gated until all its `essencial` lessons are complete (`isQuizUnlocked`).

## Content curation (Phase 11)

The badge of a lesson's check questions has **four** states, all derived in
`src/domain/curation.ts` (pure, no React):

- `curado` — "curadas à mão": the questions were written by hand (`src/content/curated.ts`).
- `rascunho` — "geradas a partir do artigo": generated by `npm run content:checks`, still
  awaiting review.
- `aprovado` — "revisadas pelo time de conteúdo": reviewed and approved in `/curadoria`.
- `ajuste` — "precisam de ajuste": the content team asked for a correction.

Non-obvious behaviour:

- The review decision is **local-first** (`yooga.academy.curation` v1, Zustand + persist), the
  same pattern as progress and session. There is no API for it yet.
- A lesson curated by hand **never enters the queue** — it is already reviewed.
- The queue follows the catalog order (group → module → lesson), so the content team works on the
  same sequence as the trail.
- `checksBadge(origin, approval)` returns `null` when the lesson has no questions — there is
  nothing to curate.
- `isApproved` only accepts the `aprovado` decision; an `ajuste` is not an approval.
- The queue screen (`src/features/curation/CurationPage.tsx`) shows the generated questions
  inline, so the reviewer never has to leave the screen to check them.

## Architecture

- `src/domain/` — pure TypeScript, **no React**: types, `rules.ts`, `selectors.ts`, `text.ts` (accent-
  insensitive search + `excerptText` snippet), `search.ts` (search inside the lesson content),
  `auth.ts` (session model, demo accounts), `curation.ts` (badge, queue and summary of the
  content curation), `progressMerge.ts` (local ↔ remote
  merge). Put business logic here, not in components.
- `src/data/` — seed + Zod schema + validated `catalog` + `catalogIndex`. The catalog is never mutated;
  all relationships come from `catalogIndex` (`groupById`, `moduleById`, `lessonById`, `groupOfModule`,
  `moduleOfLesson`, `essentialsOf`, `supportOf`, `quizModulesOfGroup`, `positionOfGroup`, `totals`).
- `src/stores/` — Zustand. Three stores persist to localStorage: `yooga.academy.progress` (v1),
  `yooga.academy.auth` (v1, token + user) and `yooga.academy.curation` (v1, content review decisions).
  `quizResult` is **in-memory only** — it survives navigation
  but is lost on reload, so the result screen must handle a missing result.
- `src/api/` — the API contract (Zod schemas), the fetch client and the endpoints (auth, progress,
  team). `apiMode()` reads `VITE_API_MODE`; with `offline` nothing touches the network.
- `src/services/` — progress sync between the browser and the API (pull on login, debounced push).
- `src/app/` — shell: `router.tsx`, `AppLayout.tsx`, `RouteEffects.tsx`, `RequireLeader.tsx`,
  `ProgressSync.tsx`.
- `src/features/<name>/<Name>Page.tsx` — one folder per screen, with colocated `.module.css` and
  colocated `.test.tsx`. `src/components/` holds one folder per primitive.
- `src/content/` — typed migrated content plus the `inline()` parser. `curated.ts` holds the curated
  lesson content (priority) and `lessons.ts` merges it with the scraped one, `generated.ts` loads
  the scraped Central content (validated by `schema.ts`), `quizzes.ts` merges the curated quizzes
  with the generated ones (`quizzes.generated.ts`), `InlineContent.tsx` renders the tokens and
  `ContentSteps.tsx` renders the step kinds
  (`texto` = numbered step, `paragrafo`, `item`, `imagem`, `nota`/`dica`/`aviso` = callouts).

## Routing

`createBrowserRouter` (`src/app/router.tsx`) — deep links require an SPA fallback to `index.html` on the
host (Vite dev/preview already do this). Routes: `/`, `/grupo/:groupId`, `/grupo/:groupId/:moduleId`,
`/aula/:lessonId`, `/quiz/:moduleId`, `/resultado/:moduleId`, `/biblioteca`, `/conquistas`, `/curadoria`,
`/entrar`, `/lider`, `*` → 404.

- `/quiz/final` is the final review (`FINAL_QUIZ_ID = 'final'`), reachable only with all 8 seals.
- `/aula/:lessonId` is loaded with the route-level `lazy` property (plus a `HydrateFallback` for deep
  links), so the scraped content lives in its own chunk. Routing tests that hit this route must await
  the heading (`findByRole`) — the first dynamic import in a test file is slow.
- `/quiz/:moduleId` and `/resultado/:moduleId` are lazy for the same reason: the generated quizzes
  (~158 kB) stay out of the initial bundle. Routing tests that hit them also need the awaited
  `findByRole` with `{ timeout: 10_000 }`.
- `/curadoria` is lazy too: the queue needs the generated checks (~100 kB), which must not weigh on the
  initial bundle. It is **not** leader-only — the content team is not necessarily a team leader.
- `RouteEffects` sets `document.title`, scrolls to top, focuses `<main>` and announces the screen in the
  live region on every navigation — but deliberately not on first render.
- `RequireLeader` is the **real** guard (Phase 8): it needs an authenticated session with the `lider`
  role, redirects anonymous users to `/entrar?redirect=…` and sends other roles back to `/`.

## Styling

- CSS Modules per component + design tokens in `src/styles/tokens.css` (`--navy`, `--blue`, `--font-slab`,
  `--content-width`, `--gutter`, ...). Never hardcode brand colours or widths.
- Global utility classes in `src/styles/global.css`: `.wrap` (max-width container), `.cap` (small uppercase
  label), `.slab` (serif), `.sr` (screen-reader only). Reuse them instead of adding new global CSS.
- Fonts are Poppins (sans) + Roboto Slab (serif), loaded via Google Fonts in `index.html`.
- Primitive APIs: `<Button variant="primary|light|dark|ghost">`, `<Chip tone="done|doing|next|todo|neutral|info">`.

## Content handling

- Lesson text uses the `inline()` parser (`src/content/inline.ts`): only `<kbd>` and `<b>` become
  `key`/`strong` tokens; every other tag stays literal text. There is **no `dangerouslySetInnerHTML`** —
  do not introduce one.
- The text of all 170 lessons is scraped from the Central de Ajuda into
  `src/content/lessons.generated.json` (`npm run content:extract`) and rendered with tokens
  (`text`, `strong`, `key`, `link`, `image`) — never as raw HTML. Lesson images are served by the
  Central CDN with `loading="lazy"`; everything else is local.
- Lessons and quizzes not yet migrated from the Help Center intentionally show a "conteúdo em migração"
  notice plus a Central de Ajuda link; quiz modules without content expose a simulate 6/6, 5/6, 3/6
  fallback to exercise XP/seal/level. These fallbacks are by design — don't delete them.
- Essential lessons now have check questions: the ones curated by hand and, for the rest, the
  ones generated from the scraped text (`npm run content:checks`). A lesson can only be
  completed once every check is answered correctly. The only essential lesson without
  questions is `balancas-e-impressoras--impressao--indicacao-de-impressoras` (its article is
  image-only); that lesson shows a short "perguntas de conferência ainda não migradas" note and
  can be completed normally — don't delete that fallback.
- The Library searches **inside** the lesson text, not only in the titles. The content index
  (`src/content/searchIndex.ts`) is loaded with a dynamic `import()` only when the query reaches
  3 characters, so the ~820 kB payload never weighs on the initial bundle — the build extracts
  it as a chunk shared with the lesson route. The search rules live in `src/domain/search.ts`
  (pure, tested in `src/domain/search.test.ts`); `excerptText` in `src/domain/text.ts` builds
  the snippet and never cuts a word in half.
- Every module with `tem_quiz: true` has a quiz: the curated one (PDV · Cardápio) or the
  generated one (`npm run content:quizzes`, marked `origin: 'rascunho'`). A module without a
  quiz entry keeps the "conteúdo em migração" screen with the simulate 6/6, 5/6, 3/6 buttons —
  don't delete that fallback.

## Testing

- Vitest + jsdom, configured inside `vite.config.ts` (there is no separate `vitest.config`).
- Test files must live under `src/` and match `*.test.ts` / `*.test.tsx`
  (`include: ['src/**/*.{test,spec}.{ts,tsx}']`). Vitest config also lives in the Vite config — don't
  add a second one.
- `src/test/setup.ts` is auto-loaded: jest-dom matchers, `cleanup`, and a `window.scrollTo` stub
  (jsdom doesn't implement it and the shell calls it on every navigation). `restoreMocks: true` is on.
- CSS is disabled in tests (`css: false`) — assert on accessible roles/names, never on class names.
- Routing tests build a memory router from the real route table:
  `createMemoryRouter(routes, { initialEntries: ['/grupo/x'] })`; simple component tests use
  `<MemoryRouter>`.
- Zustand stores and localStorage leak between tests. Reset them in `beforeEach`:
  `localStorage.clear()`, `useProgressStore.setState(createEmptyProgress())`,
  `useAuthStore.setState({ status: 'anonimo', user: null, token: null, error: null,
isSubmitting: false })`, `useCurationStore.setState(createEmptyCuration())`,
  `useToastStore.getState().clear()`, `useLiveRegionStore.getState().clear()`.
- `src/test/factories.ts` provides `makeCatalog()` (small fake catalog) and `makeProgress()` — prefer them
  over the real seed in domain tests.
- API tests stub the env with `vi.stubEnv('VITE_API_MODE', 'api')` and `vi.stubGlobal('fetch', …)`;
  call `vi.unstubAllEnvs()` / `vi.unstubAllGlobals()` in `afterEach` (the env stub also flips the app
  into API mode for the whole file).
- The Library loads the content index with a dynamic `import()`, so its tests must **await** the
  result (`await screen.findByText(..., { selector: 'b' }, { timeout: 10_000 })`). Asserting right
  after typing only sees the title matches — the counts would be stale.

## TypeScript / lint gotchas

- `@/*` → `src/*` (both `tsconfig.app.json` and `vite.config.ts`).
- ESLint `consistent-type-imports` is an **error**: use `import type { X } from '...'` for type-only imports.
- `erasableSyntaxOnly`: no `enum`, no constructor parameter properties.
- `strict`, plus `noUnusedLocals` and `noUnusedParameters`.
- `react-refresh/only-export-components` warns: don't export non-component values from a component file —
  move them to a sibling module.

## Traps

- `.env` in this folder contains Supabase / Docker / API variables. Since Phase 8 the front-end reads
  `VITE_API_MODE` (`offline` by default) and `VITE_API_URL` — but **only** through `src/api/config.ts`.
  With `offline` the app makes zero network calls and the login uses the demo accounts
  (`analista@demo.local` / `lider@demo.local`, senha `demo`). Don't flip the default to `api` without a
  running backend.
- `README.md` documents the phases and the API contract; keep it in sync when you finish a phase.
- There is no git repo, CI workflow, or hook config in this folder — no pipeline to satisfy.
- The repo is being edited concurrently; re-read a file before assuming its contents are current.
